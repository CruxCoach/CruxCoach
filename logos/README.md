# CruxCoach Brand Assets

This directory contains the upstream master artwork, store render, and
documentation previews. The Android build also consumes launcher, adaptive,
monochrome, and splash resources under `androidApp/src/main/res/`.

## Asset inventory

| Files | Role | Rebrand action |
|-------|------|----------------|
| `logos/cruxcoach-logo-final.svg` | master vector | replace with the fork's committed square SVG |
| `mipmap-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}/ic_launcher.png` | legacy launcher | generated by `scripts/generate_brand_rasters.sh` |
| the matching `ic_launcher_round.png` files | legacy round launcher | generated |
| the matching `ic_launcher_foreground.png` files | adaptive foreground at 108 dp per density | generated from the safe-zone foreground SVG |
| `drawable/ic_launcher_monochrome.xml` | themed icon geometry | replace by hand with the fork's single-color vector |
| `mipmap-anydpi-v26/ic_launcher*.xml` | adaptive wrappers | normally retain; verify they reference the new foreground, monochrome, and background |
| `drawable/ic_splash.xml` | splash composition | normally retain; it references the replaced foreground, but review its shape/background |
| `values/colors.xml#ic_launcher_background` | adaptive/splash background | review and change if the new identity needs another color |
| `logos/play_store_icon_512.png` | Zapstore/store listing | generated |
| `logos/preview/logo-{48,256,512}.png` | documentation previews | generated |
| `logos/preview/app-icon-preview.png` | composed documentation preview | recreate for the fork or delete it |

The adaptive and splash XML wrappers contain no CruxCoach-specific geometry
other than the monochrome vector: they compose the foreground and background.
They still belong in the checklist because a fork must verify that composition
under Android's masks and splash screen.

## Command-line regeneration

Install GNOME librsvg's `rsvg-convert` command, then prepare:

1. a square master SVG for legacy/store renders; and
2. a square foreground SVG whose important artwork stays inside Android's
   central adaptive-icon safe zone.

Run:

```bash
scripts/generate_brand_rasters.sh path/to/master.svg path/to/foreground.svg
```

If the same SVG already includes the required safe-zone padding, omit the
second argument. The script writes every density, round icon, adaptive
foreground, store icon, and square documentation preview with explicit pixel
dimensions. Commit the SVG input(s), record the librsvg version used, and
review the rendered icon through several Android launcher masks.

The script intentionally does not invent a monochrome vector or choose a brand
background: update `ic_launcher_monochrome.xml` and
`ic_launcher_background` deliberately. Recreate or remove the composed
`app-icon-preview.png`, and update the name/description in `zapstore.yaml`.

## Completeness check

After configuring the fork identity and running
`scripts/rebrand_ui.sh "Your App Name"`, compare against the upstream commit
from which the fork started:

```bash
scripts/check_rebrand_assets.sh <upstream-commit-or-tag>
./gradlew :androidApp:assembleRelease
```

The check verifies required files and PNG dimensions, rejects unchanged
upstream artwork (including monochrome and store assets), checks optional
previews if retained, and rejects upstream display text in build/store inputs.
It is intentionally expected to fail in an unmodified upstream checkout.
