# iOS alignment with Android 0.2.3

The iOS branch `feat/0.2.3-ios-parity` now carries the released Android
`v0.2.3` tree (`c1e70421cb3cb3e594cc76c8171c5b4691413929`), rather than the
September 20 preparation snapshot. Android application sources match that
release. The shared Kotlin core retains its Apple targets and portability
adaptations. Repository rules require linear history, so the release was
integrated as a single-parent commit after resolving the tree merge.

## Updated iOS behaviour

- Kilter imports retain entries before downloading the catalogue, resolve UUID
  spellings, use the grade of the logged angle and retain wall context and attempt
  volume. Re-import repairs catalogue metadata without overwriting local edits.
- Deleted logs stay deleted during imports. Explicit upload retries queued remote
  deletions, including when there are no new logs. Only a successful DELETE or
  HTTP 404 clears the queue. Community-only climbs are excluded from upload.
- The same bundled geometry as Android makes Aurora-family boards available for
  community climbs before a catalogue download. Existing downloaded geometry wins.
- The generator uses the released planner/filler, per-type defaults, a single
  working grade range, rising warm-up and candidate pools by displayed grade.
- Optional beta media uses Android's independently signed per-board manifests,
  hash-checked downloads and isolated validated snapshot replacement. A failed
  media refresh preserves existing videos and the catalogue.
- Plain-file imports retain iOS document access until asynchronous import finishes
  or is cancelled, so files picked outside the sandbox remain readable.
- English and German strings are regenerated from the release. Import summaries
  select the translated plural forms.

## Verification

Focused JVM tests cover Kilter import/deletion, generator integration, bundled
geometry, media replacement and the download controller. The branch workflow
also runs the shared/appcore/Android suites and Android debug build, Kotlin/Native
simulator tests, hosted XCTest, and an unsigned arm64 device build.

Final CI results and artifact links are recorded in the task handoff. An unsigned
IPA is a build artifact; installation requires the device owner's signing setup.
No physical iPhone or board has been exercised by this task.

## Remaining platform and feature differences

- SwiftUI follows native iOS interaction patterns; it is not a pixel-identical
  Compose screen port.
- Kilter account sync is explicitly initiated in the iOS account screen. It does
  not yet mirror Android's continuous sync or the complete authored-climb backfill.
- Quantum catalogue snapshot import is still unsupported. Quantum BLE/renderer
  code exists separately; that does not establish complete Quantum parity.
- Nearby GATT server/session hosting, Android accessibility imports and APK
  self-updates have no corresponding implementation in this iOS build.
- Catalogue refresh runs while the app is in the foreground. Universal links,
  push delivery and distribution depend on separate Apple provisioning work.

The pre-existing uncommitted changes in `CruxCoach-ios-023` were left untouched.
This work was performed in the isolated `CruxCoach-ios-release` worktree.
