# CruxCoach 0.2.3 pre-release

This is the review and validation checklist for `feat/0.2.3-release`.
The published stable version is still 0.2.2. This document does not authorize
publication or certify production infrastructure.

## Scope

The release includes the post-0.2.2 log-screen/navigation work, beta videos,
MoonBoard ID normalization, duplicate-key crash fix, distinct-problem statistics,
filter count/pagination fixes and the retained narrow-header/list/playlist fixes.

The earlier competitions, key-custody and personal-sharing branches were
intentionally excluded. BoardCell/FIPS mesh specifications are not a promise
that those features ship in this release.

## Prepared configuration

- `versionName`: `0.2.3`.
- Stable build `versionCode`: `9`, following 0.2.2 code `8`.
- Minimum Android version: Android 9 / API 28, announced in 0.2.2.
- Feature package and track: derive with
  `python3 scripts/feature_identity.py --branch feat/0.2.3-release`.
  A publishable development build requires its own APKTrack version reservation;
  the stable fallback code and unit-test codes are not development reservations.
- [Release notes](../../RELEASE_NOTES.md) and [changelog](../../CHANGELOG.md)
  describe 0.2.3 but deliberately remain **Unreleased** until the publication
  date is selected. The stable workflow must continue rejecting that marker.

The owner must review the Gradle/release configuration changes and the existing
CI/signing migration changes before personally merging to `main`.

## Validation

Focused regression tests cover header overflow, playlist board/filter scope,
statistics, exact browse counts and duplicate-page/refill behavior. Full test
suites run through GitHub CI; record the final commit's result in the release PR.
An earlier green commit is not evidence for a later changed build.

The final device smoke test is pending. On 2026-09-10, `dadb devices` failed with
`protocol fault (couldn't read status)`. The existing tunnel was not changed.

| Device check | Expected result |
| --- | --- |
| Update 0.2.2 to the production-signed candidate | Installation succeeds; identity, logbook, own problems, playlists and settings survive. A separately packaged feature APK does not prove this upgrade path. |
| Random text search and repeated scrolling | No repeated problems and no duplicate-key crash. |
| Filters with more than 50 matches | Count equals the complete reachable list; no truncation after 50. |
| Sent/Attempt/New, own/community, holds and Quantum restrictions | Count and list use the same active restrictions, including after rapid filter changes. |
| Repeat attempts, later send, true flash; change statistics period | One distinct problem in its best outcome category per period; total tries still reflect training volume. |
| Narrow header and German labels | Board picker remains usable; every hidden action is reachable from overflow. |
| Last playlist card | Add button does not cover delete or other card actions. |
| Generate immediately, then change angle and grade bands | Correct board and filters; usable plan and suitable candidates. |
| Beta videos and unavailable previews | Correct problem/video; unavailable media does not block browsing. |

## Before stable publication

1. Review the candidate changes and successful CI for the final revision.
2. Complete the device checks and retain the actual observations.
3. Resolve the production publication prerequisites with the owner. The private
   signing/OIDC migration is draft PR #14; its presence in source does not prove
   it is deployed. Do not start production signing or release runners here.
4. Set the real release date in the changelog and release notes, and remove the
   candidate-only sentence from the release notes. Review that final diff.
5. The owner personally merges to `main` and explicitly authorizes the exact
   stable release through the private operator plane.
6. Verify the published version, assets and distribution receipts. An APKTrack
   submission is successful only with `status=published` and
   `receipt_delivered=true`; a green test job alone is not a published APK.

No stable tag, production-signed APK or stable publication is created by preparing
this branch. See [release documentation](../RELEASE_GITHUB.md) for the checked-in
workflow and its operational limitations.
