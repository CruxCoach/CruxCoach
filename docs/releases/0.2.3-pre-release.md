# CruxCoach 0.2.3 pre-release

This is the review and validation checklist for `feat/0.2.3-release`.
The published stable version is still 0.2.2. This document does not authorize
publication or certify production infrastructure.

## Scope

The release includes the post-0.2.2 log-screen/navigation work, beta videos,
MoonBoard ID normalization, duplicate-key crash fix, distinct-problem statistics,
filter count/pagination fixes and the retained narrow-header/list/playlist fixes.

It further includes the Kilter logbook import repair: uuid resolution across all
three catalogue spellings, product size read as a size rather than a layout,
`climbConcat` holes converted to placements, frame ranges preserved, the grade
taken from the angle a log was climbed at, and deletion made effective in both
directions. Entries written by earlier versions are corrected on the next Kilter
or catalogue sync.

The earlier competitions, key-custody and personal-sharing branches were
intentionally excluded. BoardCell/FIPS mesh specifications are not a promise
that those features ship in this release.

CI/signing migration changes before personally merging to `main`.

## Validation

Focused regression tests cover header overflow, playlist board/filter scope,
statistics, exact browse counts and duplicate-page/refill behavior. Full test
suites run through GitHub CI; record the final commit's result in the release PR.
An earlier green commit is not evidence for a later changed build.

ADB worked on 2026-09-11 through the existing bridge. APKTrack feature build
1000019 (`a5139c3a`) was tested on the Nokia 6.1 / API 35: sent-exclusion
switch/status combinations, a fully scrolled 66-result filtered list, repeated
attempts followed by sends, and MoonBoard 2024 markers. Kilter Original and
Tension TB1 details were also opened. A renderer audit screened all 62 bundled
board backgrounds, with 98 cases including Kilter presets and theme variants.
These observations do not certify the stable upgrade path or physical BLE.

### Run of 2026-09-25 — production-signed candidate `0dda32d3b` (versionCode 9)

Built from the branch tip with the production key (certificate
`7f8308e8…1bc2c4`, `debuggable=false`) and installed over the previously
installed production-signed 0.2.3 on the Nokia 6.1 / API 35. CI for that exact
commit was green, and APKTrack reported `status="published"` with
`receipt_delivered=true` on track `feat-0-2-3-release-069aa55f`.

- Logbook grades: all 11 entries of the test account matched the value computed
  independently from the published catalogue for the logged angle. Ten of them
  had been wrong before, by up to six Font grades (`4a` where the problem is
  `6a` at 40°). The rows were corrected in place, without a re-import
  (`downloaded=0`), so the healing path works on existing data.
- Statistics periods agreed with the corrected grades across Total, 1 year,
  90 days and 30 days, including distinct-problem and flash-rate counts.
- 84 swipes through the browser, filtered and unfiltered, produced no
  duplicate-key crash and no fatal exception; the app stayed in the foreground.
- The filtered list paged far past 50 results without truncation, and the live
  count on the filter button tracked the selection.
- Climb detail drew the problem on its own board with the correct hold roles.

Not covered by this run, and still open: MoonBoard and other backgrounds, the
Wi-Fi reconnect banner, narrow-width header behaviour, the last playlist card,
playlist generation after angle/grade changes, beta videos, and random text
search.

Remaining findings from the 2026-09-11 run:

- The sends-over-time chart still includes failed-attempt entries; distinct
  outcome counts behaved correctly in the tested scenarios.
- Random text search on the Nokia was slow, including offline; profile separately.
- An interrupted Tension first import left climb rows without a usable browser
  catalogue. Manual reload restored browsing without resetting filters. Presence
  checks based only on climb rows can mislabel a partial import as a filter issue.
- Non-MoonBoard markers still lack neutral outlines; the contrast audit found
  palette/background collisions on several boards and in the light theme.
- Reconnecting Wi-Fi left the sync screen's offline banner visible. The new
  network observer fixes the source path; validate reconnect/disconnect on the
  APKTrack build containing that change before marking the device check complete.

## Before stable publication

1. Review the candidate changes and successful CI for the final revision.
2. Complete the device checks and retain the actual observations.
3. Resolve the production publication prerequisites with the owner. The private
   signing/OIDC migration is draft PR #14; its presence in source does not prove
   it is deployed. Do not start production signing or release runners here.
4. ~~Set the real release date in the changelog and release notes, and remove the
   candidate-only sentence from the release notes.~~ Done for 2026-09-25; correct
   both files if the publication moves to another day. Review that final diff.
5. The owner personally merges to `main` and explicitly authorizes the exact
   stable release through the private operator plane. Merging alone publishes
   nothing: [release.yml](../../.github/workflows/release.yml) is
   `workflow_dispatch` only, deliberately, because the Zapstore signer prompts
   the maintainer's phone twice per run. Dispatch it on `main` with the phone to
   hand.
6. Verify the published version, assets and distribution receipts. An APKTrack
   submission is successful only with `status=published` and
   `receipt_delivered=true`; a green test job alone is not a published APK.

No stable tag, production-signed APK or stable publication is created by preparing
this branch. See [release documentation](../RELEASE_GITHUB.md) for the checked-in
workflow and its operational limitations.
