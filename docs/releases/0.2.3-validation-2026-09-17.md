# 0.2.3 follow-up validation — 2026-09-17

Scope: `feat/0.2.3-kilter-upload`, following the owner's official-app confirmation
of build 1000016. This is not a stable release authorization.

## Findings and corrections

- **Kilter identity:** uppercase compact legacy IDs correctly associate with the
  existing grade/statistics; verified by API and owner in the official app.
- **Retry after a lost response:** live bulk insert with the same log UUID twice
  returns 200 then 500. The queue now reads the remote logbook before sending,
  skips matching IDs, and posts only missing entries. A failed/unavailable
  read-back never marks a local row synced. A partially accepted batch can retry
  without re-inserting its successful rows. Native hyphenated IDs stay unchanged.
- **Edited remote entries:** bulk insert does not update existing IDs. Tested
  PATCH/PUT variants did not provide a working update contract. Differences in
  identity, wall context, timestamp, angle, attempts or send/flash state now produce
  an explicit conflict; local changes remain pending. No automatic delete/recreate
  is attempted. Automatic propagation of such edits remains unsupported; this is
  a known limitation, not a verified update implementation. Comments and ratings
  are outside the verified log endpoint contract and not part of reconciliation.
- **Status UI:** one short status, no timestamp/count/HTTP block. Unknown,
  disabled and running states cannot display stale success. Diagnostics retain
  structured technical details and require opt-in for bug-report attachment.
- **Send timeline:** filters failed attempts out while retaining repeat sends.
  Training attempt volume is unchanged.
- **Interrupted Tension/Aurora import:** climb/stat/geometry writes share a single
  SQLite transaction. Cancellation after climb insertion rolls back the partial
  catalogue. Startup also requires geometry, not just climb rows, before treating
  an Aurora catalogue as loaded. Existing completed catalogues remain in place.
- **Wi-Fi:** on API 35, the open Board Catalogues screen showed the offline banner
  when Wi-Fi was disabled and removed it after reconnection without reopening the
  screen. Wi-Fi restored. Device run used build 1000016 (network observer unchanged).

## Verification

90 focused tests across upload HTTP/queue/diagnostics, compact Compose status,
statistics, real SQLite importer rollback, connectivity callbacks and migration
smoke checks. An initial lost-response test fixture allowed OkHttp's internal
retry to consume the next mocked response; after isolating the transport failure,
all five HTTP tests passed. The other 85 tests passed in the preceding run.
Full suites and APK builds are delegated to branch CI.

Against the actual `v0.2.2` tag (`18fb0b4f5`), secure/personal database schema files
are unchanged. A standalone SQLite check created the old board schema, inserted a
synthetic climb/beta link, applied new migrations 29 and 30, and verified retention,
beta-link migration and integrity. This is not an Android package-upgrade test.

## Remaining release gate

The owner confirmed that no production-signed 0.2.3 candidate APK exists. Therefore
an actual in-place 0.2.2 → 0.2.3 update preserving identity, private data, settings
and lists is **not yet verified**. Feature APKs have a different package/signing
scope and cannot substitute for that check. Stable signing/publication is not
started here; the owner retains main-merge and exact stable-release authority.

The new implementation still needs its final CI/publication and device smoke
result attached. Previously misassociated test logs are not silently repaired.
Temporary live diagnostic records created for retry/update checks were deleted
and confirmed absent; the prior user-visible test/reference sends remain.
