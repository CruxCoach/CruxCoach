# CruxCoach 0.2.4 pre-release

This is the review and validation checklist for `feat/0.2.4-release`.
The published stable version is still 0.2.3. This document does not authorize
publication or certify production infrastructure.

## Scope

0.2.4 is an interim release cut from `main` (0.2.3 plus the release workflow
change #18). It carries:

- the Bluetooth fix for Kilter-built LED boxes that advertise a bare
  “Kilter Board” (no `#serial`, no `@apiLevel`): discovery, API level 2, 100 ms
  pacing for write-only RX characteristics, and a hint after an empty 15 s scan;
- the Kilter logbook upload fixes of the 0.2.4 line (HTTP 500 on legacy ids,
  atomic bulk refusals, duplicates, retries, “Show entries”);
- small board fixes: session resumes after a planned rest (M-097), climbs on a
  strictly containing size, catalogue download for every brand, board switch
  during a catalogue import (board DB in WAL, one connection);
- the updater's compiled-in GitHub fallback;
- the reworked board map with “My location”, “Gyms near me” and “Choose this
  board” (location permission declared for all SDKs, asked only on tap);
- hold cleaning from the logbook.

Training, nutrition, body tracking, food photos, the coach, Health Connect and
the injury/comeback work stay on the 0.2.4 training line and move to 0.2.5.

permissions before personally merging to `main`.

androidApp 2308 with 10 skipped, all green) before the batch was pushed; GitHub CI
runs them again. Record the final commit's result in the release PR. An earlier
green commit is not evidence for a later changed build.

Kilter-built boxes were not available for testing. The BoardSimulator always
advertises `#serial@apiLevel`, so it cannot reproduce them yet.

## Before stable publication

1. Review the candidate changes and successful CI for the final revision.
2. Complete the device checks and retain the actual observations.
3. Set the real release date in the changelog and release notes. Review that
   final diff.
4. The owner personally merges to `main` and explicitly authorizes the exact
   stable release through the private operator plane. Merging alone publishes
   nothing: [release.yml](../../.github/workflows/release.yml) is
   `workflow_dispatch` only.
5. Verify the published version, assets and distribution receipts. An APKTrack
   submission is successful only with `status=published` and
   `receipt_delivered=true`.

No stable tag, production-signed APK or stable publication is created by preparing
this branch. See [release documentation](../RELEASE_GITHUB.md).
