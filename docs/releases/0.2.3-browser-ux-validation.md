# 0.2.3 browser, filters and guided entry

Work starts from release `35920004e` on `feat/0.2.3-browser-ux`.

## Implementation

- One browser header row: app logo, board, angle, Bluetooth and filter.
  All remain visible; model/size details may truncate while the board family
  remains readable. Logbook, lists, settings and replay live in the logo menu. The angle
  sheet uses supported board angles; resetting filters preserves the angle.
- Filters prioritise grade, sent exclusion/status and sorting. Further restrictions
  are expandable; choice lists are vertical. Large-text layouts retain access to
  reset, angle controls and results.
- Setup offers optional BLE connection before board picking. Discovery suggests a
  known board family without hiding alternatives or inferring layout/size/angle.
  Catalogue choices stay expanded. Account restoration lives in the subsequent
  CruxCoach import section, alongside the existing Kilter and MoonBoard paths.
- Setup skip suppresses the tour and does not silently select all catalogues.
- The tour dims the screen around the measured bounds of the real control. Short
  adjacent hints and a pointer show where to tap. No duplicate connect/next/done
  actions, tutorial cards, synthetic taps or automatic log entries are used.
- Actual Bluetooth/angle/filter actions advance the tour. Closing the connection
  sheet allows progress without hardware. Primary header controls remain direct
  even on narrow screens; the logo menu contains the secondary destinations.
- The detail step uses the actual connect/light/queue control, then guides to the
  actual Quicklog attempt and Top buttons simultaneously. The hint explicitly
  states that tapping saves a real entry. Only successful persistence advances
  the tour, which remembers the entry UUID and follows the normal back/logo/menu
  path to its edit action in the logbook. Editing is optional, and deletion is
  available in the edit dialog with a separate confirmation. Skipping never logs
  an entry. The space between the Quicklog buttons remains blocked.
- Tour dismissal persists. Existing installations do not automatically start it;
  replay is available from the app menu behind the logo.

## Quicklog / permanent header revision

- The family label is measured against available width; only secondary board
  detail is ellipsized. Logo, angle, Bluetooth and filters keep their touch areas.
- Tour input blocking supports two separate targets without opening the space
  between them. Quicklog advances only on a successful save and persists the
  saved UUID across process recreation; replay clears that UUID.
- The logbook highlights the matching entry rather than an arbitrary first row.
  It scrolls to that entry and permits opening the regular edit dialog. If the
  saved entry no longer exists, the tour ends without pointing at another record.
- Attempt editing now calls updateBid and uses the attempt form; send editing
  continues to use updateAscent. The regular edit form also offers single-entry
  deletion behind a confirmation, using the correct attempt/send repository path.
- Device verification completed on the published candidate below.
